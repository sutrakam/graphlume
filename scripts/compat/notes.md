## Reading the table

- **Compilers** counts projects, not files. `ran` is a compiler run whose index was imported (or reused from an earlier run). `ran, nothing to import` is a compiler that ran on a project whose files define only locals, constants or re-exports, so there was nothing to join to the graph; it is not a failure and it adds no proof. `not run` carries the reason GraphLume printed.
- The repositories were never built or installed (no `npm install`, `pip install`, `go mod download`), which is the state a new user's checkout is in. Compilers that resolve imports through installed dependencies therefore prove less than they would after an install. The clearest case is `pnpm-monorepo`: each package's `tsconfig` extends a workspace package that is not installed, so each package is indexed through GraphLume's stand-in `tsconfig`, which finds the package's own code but cannot follow imports of its siblings.
- `go-multimodule`: Go is proved by the type checker built into GraphLume. Because the module cache was empty, 19 packages were checked with stubbed imports (23 imports not found), which the run reports.
- Java is held back by design: indexing it runs the repository's own build, so it needs `--allow-repo-build` or the Docker runner. `java-maven` and `gradle-kotlin` therefore have no compiler proof here, and `gradle-kotlin` also lacks Gradle on this machine. Rust workspaces are refused for the same reason plus a single-package limit; there is no compiler indexer for C# that GraphLume installs (`scip-dotnet` is installed by the user), and none for Ruby, so `csharp` (its two TypeScript front ends excepted) and `rails` rest on the tree-sitter pass alone.
- `sveltekit` reaches 26.1% because most of its code is in `.svelte` files, which the TypeScript compiler indexer does not read.
- One machine (macOS, x86_64, GOMAXPROCS=2, `nice -n 19`), one run per repository; times include network and first-time indexer downloads, so treat them as order of magnitude.
